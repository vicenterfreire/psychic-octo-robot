# Local Database Workflow

## Design

`compose.yaml` is the portable source of the local PostgreSQL service. On Windows, `scripts/podman-compose.ps1` is a project hook that:

1. Resolves `podman.exe` from `PATH` or known Podman Desktop locations.
2. Runs pinned `podman-compose` 1.6.0 through `uvx` without a global installation.
3. Waits for the PostgreSQL health check.
4. Tests the published Windows port.
5. Falls back to the current Podman WSL address when localhost forwarding is unavailable.
6. Writes the usable connection to ignored `backend/.env.podman`.

An MCP server was intentionally not introduced. The project needs deterministic process execution, not a long-running protocol adapter or another security boundary.

## Commands

- `npm run db:prepare`: start PostgreSQL, migrate to head, and seed missing evaluation data.
- `npm run db:up`: start PostgreSQL and generate the runtime connection file.
- `npm run db:status`: show the Compose project containers.
- `npm run db:logs`: show the latest 100 database log lines.
- `npm run db:migrate`: apply all pending Alembic revisions.
- `npm run db:seed`: add only missing stable evaluation records.
- `npm run db:down`: stop the project and preserve its named volume.
- `npm run db:reset`: stop the project, delete its named database volume, and start empty PostgreSQL.

After `db:reset`, run `npm run db:migrate` and `npm run db:seed`, or use `npm run db:prepare`.

## Migration Workflow

The current migration head is `2db7467132b0`. For a reviewed future model change:

```powershell
uv --directory backend run alembic revision --autogenerate -m "describe change"
uv --directory backend run alembic upgrade head
uv --directory backend run alembic check
```

Autogenerated migrations must be reviewed before application. Model metadata and migration history are both versioned; `alembic check` detects drift between them.

## Data Safety

The local `elite` / `elite` credential is deliberately non-secret and must never be reused outside local development. `db:down` is recoverable because it preserves the volume. `db:reset` irreversibly deletes only the Compose volume owned by `elite-dev-challenge`.

Process environment variables take precedence over local files. A user-managed `backend/.env` takes precedence over the generated `backend/.env.podman` file.
